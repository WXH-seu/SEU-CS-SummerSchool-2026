# 学籍管理模块说明

## 1. 功能范围

学籍模块负责学生、教师、院系和班级信息的查询与维护。模块覆盖公共 DTO、Socket
协议、服务端权限与业务校验、Access DAO、Swing 页面和自动化测试。

## 2. 角色权限

| 角色 | 学生 | 教师 | 院系与班级 | 修改 |
| --- | --- | --- | --- | --- |
| 管理员 | 查询全部 | 查询全部 | 查询全部 | 允许 |
| 教师 | 查询全部 | 查询全部 | 查询全部 | 禁止 |
| 学生 | 仅本人 | 禁止 | 协议允许查询 | 禁止 |

权限在服务端 `AcademicService` 中执行。客户端隐藏无权操作的按钮只是交互优化，
不能代替服务端鉴权。

## 3. 调用链

```text
AcademicManagementPanel
  -> AcademicClientService
  -> RequestMessage / ClientConnection
  -> RequestDispatcher
  -> AcademicRequestHandler
  -> AcademicService
  -> AccessAcademicRepository
  -> vCampus.accdb
```

客户端查询和保存均通过 `SwingWorker` 执行，不阻塞 Swing 事件线程。

## 4. 协议操作

| 实体 | 查询 | 保存 | 删除 |
| --- | --- | --- | --- |
| 学生 | `STUDENT_QUERY` | `STUDENT_SAVE` | `STUDENT_DELETE` |
| 教师 | `TEACHER_QUERY` | `TEACHER_SAVE` | `TEACHER_DELETE` |
| 院系 | `DEPARTMENT_QUERY` | `DEPARTMENT_SAVE` | `DEPARTMENT_DELETE` |
| 班级 | `CLASS_QUERY` | `CLASS_SAVE` | `CLASS_DELETE` |

保存操作同时支持新增和修改。实体编号在首次保存后不可通过客户端编辑。

## 5. 主要业务规则

- 学生必须属于已存在的院系和班级。
- 学生所属院系必须与班级所属院系一致。
- 入学年份和班级年级必须在 1900 至 2100 之间。
- 出生日期使用 `yyyy-MM-dd`，空值表示未填写。
- 学籍状态仅允许在读、休学、毕业和退学。
- 登录账号与学生或教师关联时，账号角色必须一致。
- 有班级、学生或教师引用的院系不能删除。
- 有学生的班级不能删除。

## 6. 演示流程

1. 启动服务端和客户端，使用 `admin/admin123` 登录。
2. 打开“学籍管理”，切换学生、教师、院系和班级查看演示数据。
3. 新增一个院系，再新增属于该院系的班级和学生。
4. 尝试删除仍有学生的班级，确认服务器返回引用冲突提示。
5. 使用 `student/student123` 登录，确认只能看到本人学籍且没有维护按钮。
6. 使用 `teacher/teacher123` 登录，确认可以查询但不能修改。

## 7. 扩展注意事项

- 选课、借阅和订单表应引用 `studentId`，不要重复保存学生姓名等字段。
- 其他模块加入外键后，删除学生和教师时应增加相应的引用检查。
- 公共 DTO 或 `Operation` 变更后，客户端和服务端必须同时重新打包。
