版本 1.1 将学生出生日期保存为 `TEXT(10)`，由服务端校验 `yyyy-MM-dd`，以兼容
UCanAccess 5.0.1 与不同机房 Access 运行环境。

版本 1.2 的课程表引用 `tblTeacher` 和 `tblDepartment`，选课记录表引用
`tblStudent` 和 `tblCourse`，并对 `(courseId, studentId)` 建立唯一约束阻止重复选课。
选课时间使用 `TEXT(19)` 保存 `yyyy-MM-dd HH:mm:ss`。

版本 1.2 另由成员 D 增加图书、副本和借阅记录表及 10 种演示书目。

版本 1.3 统一使用登录账号标识借阅人，使学生、教师和管理员共用同一套借阅关系；
学籍资料通过 `tblStudent.userId` 或 `tblTeacher.userId` 按需关联，不在借阅表重复保存。

版本 1.4 将借阅时间改为受控文本 `yyyy-MM-dd HH:mm:ss`，与选课时间相同，避免 UCanAccess
更新 DATETIME 时的类型转换失败。启动时若检测到旧 DATETIME 列，会重建借阅表并重新写入
演示在借 / 逾期记录。

版本 1.5 的运行时只读取随 JAR 打包的 CSV 快照，不访问互联网。开发者需要更新样例时，
先执行采集脚本并审核差异，再提交新的 CSV；来源年份随各学院最新公开培养方案保存。
培养方案目录使用 `tblCatalogCourse`，实际可选教学班继续使用 `tblCourse`。

版本 1.6 在删除学生、教师、院系前主动检查选课、授课、专业目录和课程引用，统一返回
可理解的业务冲突。`tblCartItem.userId` 和 `tblOrder.userId` 正式引用 `tblUser.userId`；
专业及培养方案课程通过学籍子系统只读接口提供给所有已登录角色。

## 变更流程

1. 模块负责人向成员 B 提交字段和约束需求。
2. 成员 B 检查是否影响既有主键、外键和演示数据。
3. 更新数据库初始化代码、E-R 图、数据字典和本记录。
4. 使用旧版数据库执行一次升级验证。
5. 通知成员 A 和受影响的模块负责人。
