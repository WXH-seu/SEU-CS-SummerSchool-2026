# 选课管理模块说明

## 1. 功能范围

选课模块（v2）负责开课目录查询、选课、退课、个人课表、教师选课名单与管理员维护。
模块覆盖公共 DTO、Socket 协议、服务端可见 / 可选规则、Access DAO、Swing 页面与
自动化测试。

v2 按组内讨论结论正式放弃“专业”维度：受众以“全校 / 院系 × 入学年份区间”表达，
受众规则挂在教学班上、多条规则取并集。课程目录与教学班拆分为两张表，支持同一课程
开出多个教学班。

## 2. 角色权限（按选课子系统有效角色）

| 角色 | 开课目录 | 选课 / 退课 | 我的课表 | 名单 | 课程维护 |
| --- | --- | --- | --- | --- | --- |
| 管理员 | 全部教学班 | 禁止 | 禁止 | 任意教学班 | 允许 |
| 教师 | 本人教学班 | 禁止 | 禁止 | 仅本人教学班 | 禁止 |
| 学生 | 在读且满足受众 | 允许（限本人） | 允许（限本人） | 禁止 | 禁止 |

客户端只隐藏无权按钮；服务端按 `SubSystemRole` 与数据范围再次校验。

## 3. 可见性与可选性

- 可见（学生目录）= `active` 且 学籍状态为在读 且 满足任一条受众规则；
- 可选（按钮可点）= 可见 且 当前时间在选课窗口内 且 本人首修 / 重修名额池未满
  且 未重复选同一教学班或同一门课的其他教学班 且 无上课时间冲突；
- 未到窗口、已结束、已选、本人名额池满、时间冲突时课程仍可见，服务端在查询结果中
  给出原因（`reason`），客户端据此置灰按钮并提示。

## 4. 调用链

```text
CourseCatalogPanel / CourseSchedulePanel
  -> CourseClientService
  -> RequestMessage / ClientConnection
  -> RequestDispatcher -> CourseRequestHandler
  -> CourseService -> AccessCourseRepository -> vCampus.accdb
```

## 5. 协议操作

| 功能 | 操作 | 请求体 | 响应体 |
| --- | --- | --- | --- |
| 目录查询 | `COURSE_QUERY` | `CourseQueryRequest` | `List<CourseDto>` |
| 选课 | `COURSE_SELECT` | `CourseSelectRequest(sectionId)` | `OK` |
| 退课 | `COURSE_DROP` | `CourseDropRequest` | `OK` |
| 个人课表 | `SCHEDULE_QUERY` | 无 | `List<CourseEnrollmentDto>` |
| 保存教学班 | `COURSE_SAVE` | `CourseDto`（含受众规则） | 保存后的 `CourseDto` |
| 删除教学班 | `COURSE_DELETE` | `EntityIdRequest(sectionId)` | `OK` |
| 选课名单 | `COURSE_ROSTER` | `EntityIdRequest(sectionId)` | `List<SectionRosterEntry>` |

## 6. 业务规则

- 教学班保存时同步维护课程目录（编号、名称、学分、简介）与教学班（教师、开课院系、
  容量、上课时间、课程性质、选课窗口、启用状态）及其受众规则。
- 容量拆分为最大容量与首修 / 重修两个严格名额池：学生只能占用本人所属名额池，
  池满即拒绝，不能借用另一个池或未分配余额。两个池上限之和不得超过最大容量，
  未分配部分保留为管理员预留缓冲，不参与学生自助选课。
  选课记录按学生是否已有该课程成绩记录分为首修 / 重修。
- 管理员编辑已有教学班时，首修 / 重修名额不能低于对应池的已选人数；服务端启动时
  对“名额上限低于已选人数”或“合计超过最大容量”的历史数据只记录告警，不自动改数据。
- 已选同一门课程的其它教学班时，该教学班同样置灰并提示“已选择同一门课程的其它教学班”。
- 教学班可配置多条上课时段（周范围 + 星期 + 起止节次 + 地点），同一门课一周可在不同
  时间、地点多次上课；冲突判定统一为“同星期 + 节次区间重叠 + 周范围有交集”，选课、
  调课保护与教师时段占用检查共用该规则。
- 课程性质取值：必修、限选、任选、通选，作为展示与筛选信息。
- 选课时间窗口同时填写起止，按 `yyyy-MM-dd HH:mm` 校验。
- 教师名单含学号、姓名、院系/班级、修读类型、电话、邮箱；管理员另可见选课时间。
- 选课的“检查 + 插入”在服务端按课程粒度加 JVM 锁串行执行，防止两个客户端同时
  抢最后名额造成超卖；数据库 `UNIQUE(sectionId, studentId)` 作为第二道防线。

## 7. 演示流程

演示库包含 24 门实际课程、30 个教学班和约 150 条选课记录。六个学生账号分别位于
计算机、软件、人工智能、网络空间安全和信息工程相关场景，每个账号至少可见 8 个教学班。

1. `student/student123` 登录：目录可见本学院与全校课程；Java 程序设计已选，数据结构按
   历史记录显示重修类型。时间窗未开、容量满、时间冲突的课程仍可见但按钮置灰并显示原因。
2. 选课后“我的课表”出现记录；重复选、选已满课程、时间冲突均被服务器拒绝。
3. 分别使用 `student03`～`student06` 登录，比较不同学院受众对应的课程目录。
4. 使用 `teacher`、`teacher02` 或 `teacher03` 登录：只看到本人教学班，可查看选课名单。
5. `admin/admin123` 登录：可查看全部 30 个教学班，新增 / 编辑 / 删除教学班，配置受众、窗口与课程性质；
   删除仍有学生选课的教学班被拒绝。

## 8. 界面约定

选课页面按《Swing 界面组件说明》接入公共组件（`SeuPanels/SeuTables/SeuButtons/
SeuFields/SeuLabels/SeuMessages/SeuTheme`），视觉与图书馆模块保持一致；网络请求均
放在 `SwingWorker` 中。
