# 选课管理模块说明

## 1. 功能范围

选课模块负责课程目录查询、选课、退课、个人课表查询以及管理员课程维护。模块覆盖公共
DTO、Socket 协议、服务端权限与业务校验、Access DAO、Swing 页面和自动化测试。

## 2. 角色权限

| 角色 | 课程目录 | 选课/退课 | 我的课表 | 课程维护 |
| --- | --- | --- | --- | --- |
| 管理员 | 查询全部课程 | 禁止 | 禁止 | 允许 |
| 教师 | 仅本人开设的课程 | 禁止 | 禁止 | 禁止 |
| 学生 | 仅开放选课的课程 | 允许（限本人） | 允许（限本人） | 禁止 |

权限在服务端 `CourseService` 中执行。教师查询时服务端强制使用会话对应的
`teacherId`；学生查询时服务端强制只返回开放课程。客户端隐藏无权操作的按钮只是交互
优化，不能代替服务端鉴权。

## 3. 调用链

```text
CourseManagementPanel
  -> CourseClientService
  -> RequestMessage / ClientConnection
  -> RequestDispatcher
  -> CourseRequestHandler
  -> CourseService
  -> AccessCourseRepository
  -> vCampus.accdb
```

客户端查询、选课和退课均通过 `SwingWorker` 执行，不阻塞 Swing 事件线程。

## 4. 协议操作

| 功能 | 操作 | 请求体 | 响应体 |
| --- | --- | --- | --- |
| 课程查询 | `COURSE_QUERY` | `CourseQueryRequest` | `List<CourseDto>` |
| 选课 | `COURSE_SELECT` | `CourseSelectRequest` | `OK` |
| 退课 | `COURSE_DROP` | `CourseDropRequest` | `OK` |
| 个人课表 | `SCHEDULE_QUERY` | 无 | `List<CourseEnrollmentDto>` |
| 保存课程 | `COURSE_SAVE` | `CourseDto` | 保存后的 `CourseDto` |
| 删除课程 | `COURSE_DELETE` | `EntityIdRequest` | `OK` |

保存操作同时支持新增和修改。课程编号在首次保存后不可通过客户端编辑。

## 5. 主要业务规则

- 学生选课前必须存在学籍记录，且学籍状态为“在读”。
- 同一学生不能重复选择同一门课程，数据库唯一约束兜底。
- 已选人数达到课程容量时拒绝选课。
- 新选课程的上课时间不能与已选课程相同，用于基础冲突校验。
- 课程不存在、未开放选课时拒绝选课。
- 学生只能退掉自己的选课记录。
- 教师查询课程时服务端强制限定为本人课程。
- 管理员维护课程时校验教师、院系存在，学分和容量范围合法。
- 已有学生选课的课程不能删除，应先停用。

## 6. 演示流程

1. 启动服务端和客户端，使用 `student/student123` 登录。
2. 打开“选课系统”，课程目录显示开放课程；切换“我的课表”可看到演示选课记录。
3. 选择一门未选课程，确认后课表增加该课程；再次选择同一课程会被拒绝。
4. 在课表中退选课程，确认后目录中该课程的已选人数减少。
5. 使用 `teacher/teacher123` 登录，确认只显示演示教师开设的课程且无选课按钮。
6. 使用 `admin/admin123` 登录，新增一门课程，再尝试删除仍有学生选课的课程，
   确认服务器返回引用冲突提示。

## 7. 扩展注意事项

- 冲突校验目前按完整上课时间字符串相同判断；如需支持“同一周次不同节次”等精细规则，
  应在 `CourseService.selectCourse` 中扩展并同步更新测试。
- 课程表与选课记录表新增外键后，删除学生和教师时会被数据库引用约束阻止。
- 公共 DTO 或 `Operation` 变更后，客户端和服务端必须同时重新打包。
