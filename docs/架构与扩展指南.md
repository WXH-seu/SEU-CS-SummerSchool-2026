# vCampus 架构与扩展指南

## 1. 设计目标

- 保持 JDK 1.8、Eclipse 和 Access 兼容。
- 客户端、通信、业务和数据访问分层。
- 五名成员能够在独立模块中并行开发。
- 公共协议变更集中在 `vcampus-common`，避免客户端与服务器端定义不一致。
- 最终生成两个包含依赖的可执行 JAR。

## 2. 调用链

```text
Swing View
  -> Client Service
  -> ClientConnection
  -> RequestMessage / ObjectOutputStream
  -> ClientHandler
  -> RequestDispatcher
  -> Business Service
  -> DAO
  -> Microsoft Access
```

响应按照相反方向返回。Swing 网络请求必须放在 `SwingWorker` 中，不能阻塞事件分发线程。

## 3. 模块职责

### vcampus-common

- `dto`：客户端和服务器端共享的数据结构。
- `enums`：操作类型、响应状态和角色。
- `message`：对象流请求与响应信封。
- `config`：协议默认值。

该模块不得依赖 Swing、数据库或服务器实现。

### vcampus-client

- `ui`：Swing 页面和公共组件。
- `network`：长连接、对象流和请求响应匹配。
- `config`：服务器地址与端口。
- 后续增加 `service`：把页面操作转换为协议请求。

客户端不得包含 SQL、DAO 或 Access 文件路径。

### vcampus-server

- `network`：连接接收、线程池和客户端处理器。
- `dispatcher`：按照 `Operation` 分发请求。
- `service`：业务规则、权限和事务边界。
- `dao`：JDBC 与 Access 数据访问。
- `session`：登录会话。
- `security`：密码哈希等安全功能。

## 4. 新增业务功能步骤

以“查询图书”为例：

1. 在 `vcampus-common` 创建 `BookQueryRequest` 和 `BookSummary`。
2. 确认 `Operation.LIBRARY_BOOK_QUERY` 已存在。
3. 在服务器端创建 `BookRepository` 和 `AccessBookRepository`。
4. 创建 `LibraryService`，仅使用登录 `userId` 和 `SubSystemRole` 实现业务规则。
5. 创建独立 Handler 并接入 `RequestDispatcher`；由分发器完成全局角色到当前子系统
   有效角色的转换和中央权限检查。
6. 在客户端创建 `LibraryClientService`。
7. 将 `MainFrame` 中的占位卡片替换为真实 `LibraryPanel`。
8. 使用 `SwingWorker` 调用服务器，并在完成后更新表格。
9. 添加 DAO、Service 和协议序列化测试。
10. 更新数据库设计、JavaDoc 和系统使用说明。

四个业务子系统统一遵守以下角色边界：

```text
UserAccount(Role + adminScopes)
  -> RequestDispatcher / PermissionPolicy
  -> userId + SubSystemRole(ADMIN / TEACHER / STUDENT)
  -> Academic / Course / Library / Store Handler
  -> Business Service
```

业务 Handler、Service 和 Swing 页面不得直接判断 `SUPER_ADMIN`、`SUBSYSADMIN` 或
`adminScopes`。课程和商店模块接入时应沿用现有 Academic/Library Handler 的参数形式。

## 5. 协议规则

- 每个请求拥有唯一 `requestId`。
- 每个业务操作使用一个明确的 `Operation`。
- 登录后的请求携带 `sessionToken`。
- `body` 只能使用 `vcampus-common` 中定义的可序列化 DTO。
- DTO 和 Message 必须声明 `serialVersionUID`。
- 客户端和服务器端必须使用同一版本的 `vcampus-common`。
- 不在日志中输出密码、完整会话令牌或敏感个人信息。

## 6. 数据库规则

- Access 文件仅部署在服务器端。
- 使用 UCanAccess 5.0.1，保持 Java 8 兼容。
- 使用 `PreparedStatement` 和 try-with-resources。
- Service 定义事务边界，DAO 不承载界面或网络逻辑。
- 金额使用定点整数或 `BigDecimal`，不得使用 `double`。
- 选课、借阅、库存和订单操作需要检查并发状态。
- 数据库结构变更必须同步更新 E-R 图和数据字典。

## 7. 当前迁移范围

已从参考案例保留：

- 用户、学籍、选课、图书馆和商店的功能边界。
- C/S、多客户端和统一消息分发思路。
- DAO 与业务功能分离的方向。

未迁入：

- Kotlin、Compose Desktop 和 JavaFX 17 客户端。
- MySQL 驱动、MySQL SQL 和固定数据库密码。
- OpenCV、浏览器脚本和大模型等非必做功能。
- 写死的私钥、账号、密码和绝对路径。
- IntelliJ IDEA 配置、打包产物和旧代码。
