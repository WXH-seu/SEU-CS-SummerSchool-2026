# 成员 C 任务计划

## 1. 岗位定位

- 角色：选课系统负责人、C/S 通信框架负责人。
- 目标：完成选课完整业务，并为所有模块提供稳定、统一的 Socket 通信基础。
- 工作边界：负责通信框架和规范，各模块负责人负责定义并处理本模块的具体请求。

## 2. 业务任务

- 实现课程查询、选课、退课和个人课表查询。
- 实现重复选课、容量限制和必要的冲突校验。
- 实现教师课程查询以及管理员课程维护。
- 实现选课相关 Swing 页面、服务端业务和 DAO。
- 设计客户端与服务器端共用的可序列化 Message。
- 实现请求类型、响应状态和异常信息的统一格式。

## 3. 四周计划

| 周次 | 任务 | 交付物 |
| --- | --- | --- |
| 第一周 | 设计 Message、请求分发、Socket 生命周期和选课业务流程 | 通信协议说明、类图、选课模块设计 |
| 第二周 | 实现客户端连接、服务器监听、多线程处理和选课完整业务 | 通信框架、选课业务链路、基础并发测试 |
| 第三周 | 指导其他模块接入通信框架；完善断线、超时和异常处理 | 全模块通信接入、异常处理记录 |
| 第四周 | 执行多客户端与网络异常测试；整理通信设计文档 | 通信测试报告、源代码说明、稳定版本 |

## 4. 公共职责

- 维护公共消息类、请求类型和响应状态定义。
- 实现服务器端客户端线程管理与请求分发。
- 保证客户端和服务器端共享类版本一致。
- 对网络断开、无效消息和未知请求进行容错处理。
- 为其他成员提供最小通信示例和接入说明。

## 5. 协作接口

- 与成员 A 确认身份信息、会话和权限传递方式。
- 与成员 B 确认课程、学生、教师和选课记录表结构。
- 指导成员 D、E 接入图书馆和商店请求。
- 接受成员 B 的代码审核，并审核成员 D 的代码与文档。

## 6. 完成标准

- [ ] 客户端能够稳定连接服务器并正确收发消息。
- [ ] 服务器端能够同时处理多个客户端。
- [ ] 所有传输对象实现 `Serializable`，客户端与服务器端定义一致。
- [ ] 课程查询、选课、退课和课表查询均可运行。
- [ ] 重复选课、容量不足等异常能够被正确阻止。
- [ ] 网络错误不会导致服务器整体退出。
- [ ] 通信框架和选课模块具备 JavaDoc 与测试记录。
