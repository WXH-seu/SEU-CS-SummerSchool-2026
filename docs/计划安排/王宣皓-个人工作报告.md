## 二、个人工作概述

本人主要负责学籍管理模块的需求分析、数据建模、客户端界面、网络通信、服务端业务、
Access 数据访问和自动化测试，同时承担全项目数据库结构设计与跨模块数据关系协调工作。

工作重点不是只完成一个学籍信息页面，而是建立一条完整、可验证的业务链路：用户在
Swing 客户端进行查询或编辑，客户端通过 Socket 向服务器发送请求，服务器根据当前学籍
子系统有效角色执行权限检查和业务校验，再由数据访问层读写 Access 数据库，最后将统一的
响应对象返回客户端。该实现兼容 JDK 1.8，并且不要求机房预先配置 ODBC 数据源。

## 四、核心功能实现

### 4.1 学籍查询和维护

- 学生、教师、院系和班级均支持结构化查询与管理。
- 关键字用于模糊匹配当前实体的编号和名称，不把所有字段混在一次搜索中。
- 学院和班级采用独立筛选条件，学院下拉菜单由数据库中的东南大学院系列表生成。
- 管理员可以维护学生、教师、院系和班级信息；教师拥有只读查询权限。
- 保存前校验必填字段、编号唯一性、年份、日期、邮箱、学籍状态和关联账号角色。
- 学生所属班级必须存在，并且班级所属学院必须与学生学院一致。

### 4.2 学生本人资料维护

学生登录后只能查看与当前账号关联的本人学籍，不能通过修改客户端请求参数查询他人。
学生可以自行填写或更新性别、出生日期、电话和邮箱，不能修改学号、姓名、学院、班级、
入学年份和学籍状态等管理字段。

这一限制由服务端根据登录会话再次确定目标学生并执行字段白名单控制，客户端隐藏按钮仅作为
交互优化。因此，即使客户端被修改，也不能越权更新其他学生或管理字段。

### 4.3 新生批量导入和自动分班

为解决大一新生逐条录入效率低的问题，实现了 CSV 批量导入功能。导入过程包括文件解析、
逐行格式检查、业务校验、失败原因记录和导入结果汇总。提供统一模板，便于管理员整理新生数据。

当新增或导入学生时未指定班级，系统按照以下规则自动分班：

1. 只选择相同学院、相同入学年份且处于启用状态的班级；
2. 排除当前人数已经达到管理员设置容量的班级；
3. 优先选择当前人数较少的班级，使各班人数尽量均衡；
4. 人数相同时按照班级编号排序，保证结果稳定、可重复；
5. 没有可用班级时返回明确失败原因，不生成不完整学籍。

班级容量由管理员维护，默认值为 50，并在服务端校验必须大于 0。

### 4.4 东南大学公开目录数据

项目使用经过人工复核的东南大学公开数据快照，包含 34 个院系或教学单位、9 个专业、
66 门代表性课程、98 条专业课程关系和 7 个官方来源。快照随服务器打包，启动时导入 Access，
因此机房断网或官网变化不会影响演示。

公开培养方案中的课程定义保存在 `tblCatalogCourse`，实际选课使用的开课与教学班保存在
`tblCourse` 和 `tblCourseSection`。两者职责分离，避免把公开培养方案样例误当成当前可选课程。

## 五、面向对象设计与技术实现

### 5.1 分层结构

```text
AcademicManagementPanel / AcademicEditors
        ↓
AcademicClientService / StudentCsvParser
        ↓
RequestMessage + DTO + Operation
        ↓ Socket
AcademicRequestHandler
        ↓
AcademicService / CurriculumCatalogService
        ↓
AcademicRepository / CurriculumCatalogRepository
        ↓
AccessAcademicRepository / AccessCurriculumCatalogRepository
        ↓
vCampus.accdb
```

- **封装**：学生、教师、院系、班级和导入结果由 DTO 封装，界面不直接拼接 SQL。
- **抽象**：`AcademicRepository` 等接口描述业务需要的数据能力，不暴露 Access 实现细节。
- **多态**：服务层依赖仓储接口，可以替换真实 Access 实现或测试实现。
- **单一职责**：界面负责交互，客户端服务负责请求，处理器负责分派，业务服务负责规则，
  Repository 负责持久化。
- **依赖注入**：服务对象通过构造方法接收 Repository，便于使用临时数据库进行独立测试。
- **对象协作**：通过 `Operation` 表示操作类型，通过请求和响应对象传递数据，减少模块间耦合。

### 5.2 网络与并发体验

客户端和服务器使用 Java Socket 与对象流通信。界面中的网络查询和保存通过 `SwingWorker`
执行，避免耗时操作阻塞 Swing 事件线程。所有权限判断和关键业务校验都放在服务器端，保证
多台客户端同时连接时仍遵循相同规则。

### 5.3 Java 8 与 Access 兼容

- Maven 编译目标保持为 Java 8，未使用更高版本 JDK 才支持的语法或 API。
- 采用 UCanAccess 直接连接 `.accdb` 文件，无需在每台电脑配置 DNS/ODBC 数据源。
- 数据库路径通过配置和相对位置解析，不依赖个人电脑的固定绝对路径。
- 针对 UCanAccess 处理部分 `DATETIME` 更新时的兼容问题，出生日期使用 `TEXT(10)` 保存，
  服务端使用 `LocalDate` 按 `yyyy-MM-dd` 严格验证。
- 数据库初始化和结构升级具有幂等性，重复启动不会重复插入种子数据。

## 六、数据库与跨模块集成工作

本人负责统一数据库表命名、字段类型、主键、外键、唯一性和非空约束，并维护初始化顺序、
结构变更记录和演示数据。数据库覆盖用户权限、学籍、选课、图书馆、公开课程目录和商店模块。

跨模块集成中完成或推动了以下工作：

- 学籍子系统只接收当前子系统有效角色，不再依赖全局角色进行判断。
- 学生与教师通过 `userId` 关联统一账号；图书借阅、预约和推荐记录统一引用 `userId`。
- 商店购物车和订单通过 `userId` 引用 `tblUser`，支持学生与教师等不同账号类型。
- 选课记录引用 `studentId`，教学班通过教师标识关联授课教师。
- 删除学生、教师、班级或院系前先检查其他模块引用，存在选课、授课、借阅、预约、推荐、
  购物车或订单数据时返回明确的 `CONFLICT`，防止产生孤立记录。
- 修正旧选课数据库升级时的从表删除顺序，并通过元数据检查安全补充旧商店表字段。
- 使用临时 Access 文件验证全模块冷启动、重复启动、种子数据和关键外键，避免覆盖本地工作库。

## 七、重点问题与解决方法

| 问题 | 处理方法 | 效果 |
| --- | --- | --- |
| 任意关键字含义不清 | 将关键字限定为当前实体编号和名称；学院、班级单独筛选 | 查询规则明确，结果可预测 |
| 学院手工输入易出错 | 从数据库读取完整院系列表生成下拉菜单 | 避免拼写和编号错误 |
| 新生逐条录入效率低 | CSV 批量导入并返回逐行结果 | 可一次完成整批新生建档 |
| 人工分班不均衡 | 按学院、年级、容量和当前人数自动选择班级 | 减少重复操作并保持班级均衡 |
| 学生自助维护可能越权 | 服务端绑定当前会话并采用可修改字段白名单 | 只能修改本人四项资料 |
| 模块使用全局角色 | 统一传递当前子系统有效角色 | 各模块权限边界清晰 |
| 删除学籍造成业务孤立记录 | 服务层引用预检查与数据库外键双重保护 | 数据一致性更可靠 |
| Access 旧库升级顺序敏感 | 按外键依赖顺序处理从表和主表 | 兼容历史数据库结构 |
