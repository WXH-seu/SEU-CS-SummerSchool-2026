## 第二轮：注册策略调整与管理员分级（已完成）

按组内评审意见，账号注册从“公开自助”改为“管理员专属”，并引入两级管理员：

- [x] 移除登录界面注册按钮，登录界面仅提示“账号由管理员创建，如需新账号请联系管理员”。
- [x] 注册改为管理员操作：学生走 CSV 批量导入（`USER_IMPORT_CSV`），教师/管理员手动注册（`USER_REGISTER`）；不给新用户自动建会话。
- [x] 新增 `Role.SUPER_ADMIN`（超级管理员/全局），与 `Role.ADMIN`（子系统管理员）区分。
- [x] 权限矩阵：`USER_REGISTER` 等管理员操作放行 `ADMIN + SUPER_ADMIN`；业务模块默认给超级管理员最大访问。
- [x] 业务层二次校验：`AuthService` —— 所有管理员方法带 `actorRole` 并 `requireAnyAdmin`；**目标角色门控**——创建/管理 `ADMIN/SUPER_ADMIN` 账号的操作者必须是 `SUPER_ADMIN`；子系统管理员只能创建/管理学生、教师。
- [x] 接入方式：`AccountFrame` 管理员“用户管理”页新增“注册用户”“批量导入CSV”；`RegisterFrame` 角色下拉含“超级管理员”。
- [x] 种子数据新增 `superadmin / super123` 超级管理员账号。

## 第三轮：审计日志与权限颗粒度对齐（已完成）

- [x] 新增审计日志表 `tblOperationLog`（Access）：记录登录（成功/失败）与管理员操作（注册、CSV 导入、启用/禁用、注销）。
- [x] 服务端：`OperationLogRepository` / `AccessOperationLogRepository` + `AuditService`（best-effort 记录，不阻塞业务）；`AuthService` 在登录与账号管理操作中写入审计。
- [x] 权限颗粒度对齐：账号管理（注册、CSV 导入、列出、状态、审计查询）收敛为**仅超级管理员**；子系统管理员 `ADMIN` 只**操作业务子系统**，不再具备账号管理权限。
- [x] 客户端：`AccountFrame` 的“用户管理”“操作日志”页仅超管可见；`UserClientService` 增加审计查询。
- [x] 测试：新增审计记录断言、超管专属账号管理、审计查询分发；全部通过。
