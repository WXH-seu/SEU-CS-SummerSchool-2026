# 成员 A 任务计划

## 1. 岗位定位

- 角色：组长、用户与权限模块负责人、系统集成人。
- 目标：完成用户认证与授权模块，组织项目进度，并保证各模块能够稳定集成。
- 工作量控制：项目管理属于额外职责，因此业务范围集中在用户、会话和权限，不额外承担其他完整业务模块。

## 2. 业务任务

- 设计用户、角色、权限和会话相关实体。
- 实现注册、登录、登出和注销功能。
- 实现学生、教师和管理员的角色授权。
- 实现服务端身份认证和业务权限检查。
- 实现登录界面、账号管理界面和权限相关提示。
- 提供演示账号，并配合各模块完成权限接入。

## 3. 四周计划

| 周次 | 任务 | 交付物 |
| --- | --- | --- |
| 第一周 | 汇总需求；制定团队计划；完成用户、角色和权限设计；建立 Git 协作规则 | 分工表、进度计划、用户模块设计、权限矩阵 |
| 第二周 | 实现注册、登录、登出、注销、会话和权限校验；参与工程集成 | 用户模块完整业务链路、模块测试记录 |
| 第三周 | 组织学籍、选课、图书馆和商店模块集成；统一权限处理和异常响应 | 第一版完整集成系统、问题清单 |
| 第四周 | 组织回归测试、版本冻结、交付物汇总和答辩演练 | 最终版本、发布说明、答辩流程 |

## 4. 公共职责

- 维护总体任务清单和每周进度记录。
- 组织公共接口、数据库结构和通信协议评审。
- 负责 `develop` 分支的阶段集成和 `main` 分支的稳定发布。
- 处理模块冲突，但不代替其他成员完成其业务任务。
- 汇总小组项目报告和答辩 PPT。

## 5. 协作接口

- 与成员 B 确定用户表、角色字段和数据库约束。
- 与成员 C 确定登录消息、会话标识和错误响应格式。
- 向成员 D、E 提供统一的权限检查方式。
- 接受成员 E 对用户模块和最终集成版本的测试。
- 负责审核成员 B 的代码与文档。

## 6. 完成标准

- [ ] 不同角色能够正常注册、登录、登出和注销。
- [ ] 未登录或权限不足时，系统能够拒绝访问并给出明确提示。
- [ ] 密码不以明文方式直接展示或记录到日志。
- [ ] 用户模块在客户端、服务器端和 Access 数据库之间形成完整闭环。
- [ ] 关键类、接口和方法具备 JavaDoc。
- [ ] 每周计划、集成版本和会议结论均有记录。
