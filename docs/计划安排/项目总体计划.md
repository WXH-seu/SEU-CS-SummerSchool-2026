# 虚拟校园项目总体计划

## 1. 项目约束

| 项目 | 要求 |
| --- | --- |
| 开发工具 | Eclipse |
| Java 版本 | JDK 1.8，所有代码与构建产物必须兼容 Java 8 |
| 系统架构 | C/S 架构，包含客户端和服务器端 |
| 客户端界面 | Swing |
| 网络通信 | TCP Socket、多客户端、多线程、对象流消息传输 |
| 数据库 | Microsoft Access，程序直接连接数据库文件，不依赖 DNS/ODBC 数据源 |
| 项目管理 | Maven、Git、GitHub |
| 最终程序 | `vCampusClient.jar`、`vCampusServer.jar`、`vCampus` 数据库 |

## 2. 必做模块

1. 用户管理：注册、注销、登录、登出和角色授权。
2. 学籍管理：学生、教师、班级和院系信息管理。
3. 选课系统：课程查询、选课、退课和规则校验。
4. 图书馆：图书检索、借阅、归还和库存管理。
5. 校园商店：商品、购物车、订单和库存管理。

## 3. 成员分工

| 成员 | 角色 | 负责模块 | 公共职责 | 主要成果 |
| --- | --- | --- | --- | --- |
| 成员 A | 组长、开发人员 | 用户与权限管理 | 进度管理、Git 管理、系统集成 | 用户认证、权限控制、版本集成 |
| 成员 B | 开发人员 | 学籍管理 | 数据库总体设计 | 学籍业务、E-R 图、Access 表结构与测试数据 |
| 成员 C | 开发人员 | 选课系统 | C/S 通信框架 | 选课业务、Socket、Message 与请求分发 |
| 成员 D | 开发人员 | 图书馆 | Swing 界面规范 | 图书馆业务、公共界面组件与使用说明 |

每名成员均须完成自己模块的需求分析、界面、客户端逻辑、通信接入、服务端逻辑、数据库访问、测试、JavaDoc 和文档说明。公共职责不替代个人业务模块开发。

## 6. 协作与审核规则

- 分支建议：`main` 保存可演示版本，`develop` 用于阶段集成，个人功能使用 `feature/*` 分支。
- 每次提交只处理一个明确问题，提交信息应说明完成的模块或修复内容。
- 交叉审核顺序：A 审核 B，B 审核 C，C 审核 D，D 审核 E，E 审核 A。
- 公共接口、消息结构和数据库结构发生变化时，必须通知全组并更新设计文档。
- 每个模块至少由负责人以外的一名成员运行测试。
- 每周汇报需记录已完成任务、存在问题、解决办法和下周计划。

## 7. 模块完成标准

- Swing 客户端界面可以完成核心操作。
- 请求可通过 Socket 正确发送，服务器能返回明确结果。
- 服务端进行身份认证、权限校验和参数校验。
- Access 数据库状态更新正确，异常时不会产生明显脏数据。
- 正常流程和主要异常流程均有测试记录。
- 类、接口和关键方法具备 JavaDoc。
- 配置中不包含个人电脑绝对路径或明文敏感信息。
- 代码兼容 JDK 1.8，并能从 Eclipse 导入、编译和运行。
