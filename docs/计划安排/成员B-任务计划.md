# 成员 B 任务计划

## 1. 岗位定位

- 角色：学籍管理模块负责人、数据库总体设计人。
- 目标：完成学籍管理业务，并保证 Access 数据结构能够支持全部业务模块。
- 工作边界：负责数据库总体规范，各业务表的具体字段由对应模块负责人共同确认。

## 2. 业务任务

- 设计院系、班级、学生和教师相关实体及表结构。
- 实现学生信息查询、新增、修改和删除。
- 实现教师、班级和院系基础信息管理。
- 实现不同角色对学籍数据的访问权限。
- 实现学籍管理 Swing 页面、服务端业务和 DAO。
- 准备学籍模块演示数据和异常测试数据。

## 3. 四周计划

| 周次 | 任务 | 交付物 |
| --- | --- | --- |
| 第一周 | 完成总体 E-R 图、数据字典、命名规范和学籍模块设计 | E-R 图、Access 表结构、数据字典、初始化方案 |
| 第二周 | 建立数据库连接与基础 DAO；完成学籍模块客户端、服务端和数据库功能 | 学籍管理完整业务链路、测试数据 |
| 第三周 | 协助各模块接入数据库；处理外键、约束和共享实体问题 | 数据库集成版本、结构变更记录 |
| 第四周 | 执行数据一致性测试；整理数据库说明和最终演示数据 | 最终数据库、初始化数据、数据库设计说明 |

## 4. 公共职责

- 统一表名、字段名、主键和外键规范。
- 维护数据库结构说明和变更记录。
- 提供 Access 数据库直接连接方案，避免依赖 DNS/ODBC 配置。
- 检查数据库文件路径是否采用配置或相对路径。
- 协助各成员编写 DAO，但不代替其完成业务逻辑。

## 5. 协作接口

- 与成员 A 确认用户、角色和学籍信息之间的关系。
- 与成员 C 确认学生、课程、教学班和选课记录结构。
- 与成员 D、E 评审图书和商店相关表结构。
- 接受成员 A 的代码审核，并审核成员 C 的代码与文档。

## 6. 完成标准

- [ ] Access 数据库能够通过程序直接连接。
- [ ] 学生、教师、班级和院系信息可以正确维护和查询。
- [ ] 主键、外键、唯一性和非空等约束设计清晰。
- [ ] 数据库文件包含可用于答辩的测试数据。
- [ ] 数据库位置不依赖个人电脑绝对路径。
- [ ] E-R 图、数据字典和实际数据库结构一致。
- [ ] 学籍模块关键代码具备 JavaDoc 和测试记录。
