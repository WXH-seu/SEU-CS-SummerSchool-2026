# 选课模块 v2 设计草案

> 状态：讨论稿，仅用于组内对齐，尚未修改任何代码。
> 本草案由成员 C 整理，主要结论已经与组内讨论确定，可作为后续 v2 实现与跨成员对齐的依据。

## 1. 背景与目标

当前 v1 选课模块把“课程”和“可选规则”混在同一张 `tblCourse` 表里，用 `active`
一个开关和 `semesterName` 字符串近似表达可用性，缺少专业、受众、选课时间窗口、
课程性质等真实选课平台常见的概念。

v2 的目标：

- 把“某学生此刻能看到哪些课、能选哪些课”建模为“学生属性 × 课程属性 × 当前时间”求交的结果；
- 支持不同院系、专业、年级的学生可选课程不同；
- 支持每门课独立的选课时间窗口；
- 支持课程性质（必修/限选/任选/通选）及其查询；
- 支持教师查看自己课程的选课名单。

## 2. 核心结论：可见性与可选性分离

这是整套设计的基石，建议明确两条规则：

可见（学生能在目录里看到）= `active = true`（管理员未停用）
且 学生满足受众规则。

学生端目录查询还要求学籍状态为“在读”；休学、毕业、退学学生不可见。转专业不作为独立
就读状态，转专业学生仍视为在读，按“当前有效专业”判断可见与可选。

学期（semesterName）仅作展示信息，不参与目录可见性判断。这依赖一个运维约定：
管理员只维护当前学期的教学班，旧学期停用或归档，不提前发布未来学期的班。

可选（按钮可点）= 可见
且 当前时间在选课窗口内
且 容量未满
且 未重复选课
且 无上课时间冲突。

选课窗口只影响“可选性”，不影响“可见性”：窗口开始前和结束后课程仍可见，按钮置灰，
分别提示“还没到选课时间”和“选课已结束”。容量满、时间冲突、已重复同理，课程保持
可见，按钮处给出对应原因。

由此得到界面结论：

- 学生端目录页不展示 `active`、`semesterName` 两列，也不提供按学期或是否开放筛选；
- `active` 只保留“管理员是否发布/停用”的含义，不再兼表“是否开放选课”；
- 不可选的课程按钮置灰，并显示具体原因。

## 3. 现状与差距

当前实际存在的表（供对照）：

| 表 | 归属 | 说明 |
| --- | --- | --- |
| tblUser | 成员 A | 账号与角色 |
| tblDepartment | 成员 B | 院系 |
| tblSchoolClass | 成员 B | 班级，含 gradeYear |
| tblStudent | 成员 B | 学生，含 departmentId、classId、enrollmentYear |
| tblTeacher | 成员 B | 教师，含 departmentId |
| tblCourse | 成员 C | 课程，当前混入容量、学期、时间、active 等 |
| tblCourseEnrollment | 成员 C | 选课记录，引用 courseId |

关键差距：

- 没有“专业”实体，学生只有院系和班级，无法表达“不同专业可选课程不同”；
- 年级只有入学年份、班级年级字段，没有独立实体（本方案以入学年份区间直接匹配受众）；
- 课程没有选课时间窗口；
- 课程没有课程性质；
- 课程没有受众规则；
- 教师无法查看选课名单。

## 4. 目标数据模型（建议）

引入“课程 / 教学班 / 受众 / 性质”的分层，不再用一张 `tblCourse` 承担所有职责。

### 4.1 tblMajor（新增：专业）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| majorId | TEXT(16) | 主键 | 专业编号 |
| majorName | TEXT(64) | 非空、唯一 | 专业名称 |
| departmentId | TEXT(16) | 外键、非空 | 所属院系 |
| active | YESNO | 非空 | 是否启用 |

专业属于院系。学生通过专业关联，从而得到院系和专业的完整归属。

### 4.2 专业关联与转专业（已确认）

- `tblMajor` 关联 `tblDepartment`（专业属于院系，必须）；
- `tblSchoolClass` 增加 `majorId`（班级属于专业）；
- `tblStudent` 增加 `majorId`（学生当前有效专业，直接存，建档时从班级专业复制）。

就读状态保持 `在读 / 休学 / 毕业 / 退学` 不变，不新增“转专业”状态。转专业 = 管理员
把学生的 `majorId` 改为目标专业。显示与匹配统一取该字段：未转专业学生显示当前专业，
转专业学生显示目标专业。暂不保留转专业历史记录。

### 4.3 tblCourse（课程目录，简化）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| courseId | TEXT(20) | 主键 | 课程编号，一门课唯一 |
| courseName | TEXT(64) | 非空 | 课程名称 |
| credit | DOUBLE | 非空 | 学分 |
| description | TEXT(255) | 可空 | 课程简介 |
| active | YESNO | 非空 | 课程是否启用 |

课程目录只描述“这门课是什么”，不描述“谁在什么时候上、谁能选”。

### 4.4 tblCourseSection（教学班：实际开班）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| sectionId | TEXT(20) | 主键 | 教学班编号，每次开班唯一 |
| courseId | TEXT(20) | 外键、非空 | 对应课程 |
| teacherId | TEXT(20) | 外键、非空 | 授课教师 |
| semesterName | TEXT(32) | 非空 | 学期 |
| classTime | TEXT(64) | 非空 | 上课时间，用于冲突校验 |
| location | TEXT(64) | 可空 | 上课地点 |
| capacity | INTEGER | 非空 | 容量，单一来源 |
| selectionStartTime | TEXT(19) | 非空 | 选课开始时间 |
| selectionEndTime | TEXT(19) | 非空 | 选课结束时间 |
| active | YESNO | 非空 | 管理员是否发布或停用 |

一个教学班对应一个物理班：一份容量、一份名单、一处时间地点。合班上课就是一个教学班。

### 4.5 tblSectionAudience（教学班受众：谁能选）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| audienceId | TEXT(32) | 主键 | 受众规则编号 |
| sectionId | TEXT(20) | 外键、非空 | 所属教学班 |
| scopeType | TEXT(16) | 非空 | ALL / DEPARTMENT / MAJOR |
| scopeValue | TEXT(16) | 可空 | 非 ALL 时的院系或专业编号 |
| enrollYearMin | INTEGER | 可空 | 面向入学年份下限 |
| enrollYearMax | INTEGER | 可空 | 面向入学年份上限 |

受众 = 范围（全校/院系/专业）× 入学年份区间。一个教学班可挂多条受众规则。
已确认保留“院系”这一层级；年级匹配统一用入学年份区间，直接与学生 `enrollmentYear`
比较，不计算“当前年级”。

### 4.6 课程性质（与受众分开存放）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| natureId | TEXT(32) | 主键 | 性质记录编号 |
| sectionId | TEXT(20) | 外键、非空 | 所属教学班 |
| majorId | TEXT(16) | 外键、非空 | 适用专业 |
| courseNature | TEXT(16) | 非空 | 必修 / 限选 / 任选 / 通选 |

受众回答“谁能选”，性质回答“选了算什么”。性质按专业单独挂，避免把整个院系统一写成
同一种性质。

课程性质定位为纯信息：只用于展示与筛选，不挂毕业学分、优先级、退课限制等功能逻辑。
“通选”同样只是展示信息，不与“受众=全校”建立任何一致性约束。

### 4.7 tblCourseEnrollment（选课记录，调整引用）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| enrollmentId | TEXT(32) | 主键 | 选课记录编号 |
| studentId | TEXT(20) | 外键、非空 | 学生 |
| sectionId | TEXT(20) | 外键、非空 | 教学班 |
| enrollTime | TEXT(19) | 非空 | 选课时间 |

唯一约束改为 `UNIQUE(sectionId, studentId)`。已确认不允许同一学生选同一课程的不同
教学班；该约束只防同班重复，跨教学班的“同课程”冲突需在服务端按 `courseId` 校验。

### 4.8 年级与学期（已确认）

- 受众匹配不计算“当前年级”，改用入学年份区间直接比较 `tblStudent.enrollmentYear`；
- 学期（semesterName）仅作展示信息，不参与可见性筛选，也不需要维护“当前学期/学年”
  配置；管理员只维护当前学期教学班、旧学期停用的约定承担了“当前学期”的含义；
- 若以后需要预选下学期课程或保留历史学期查询，再引入“当前学期”筛选即可；
- 休学、留级会导致“入学年份”与真实年级不符，课程项目作为已知边界，暂不处理。

## 5. 业务规则（建议）

学生端课程目录查询 = 学籍状态为“在读”的学生，在 active 的教学班中，满足受众规则的部分。

选课校验顺序建议：

1. 角色为学生，且学籍状态为“在读”；
2. 教学班存在且 active；
3. 学生满足受众（范围 × 入学年份区间，按当前有效专业判断）；
4. 当前时间在选课窗口内；
5. 未重复选同一教学班（唯一约束兜底），且未选同一课程的其他教学班（按 courseId 校验）；
6. 未超出容量；
7. 上课时间不与已选课程冲突。

退课、课表查询沿用现有逻辑，但引用教学班。

教师：查询自己名下的教学班；并可查询这些教学班的选课名单（新增 `COURSE_ROSTER`，
服务端校验 teacherId 一致）。名单默认仅含学号、姓名、专业/班级、选课时间，
不展示电话、邮箱等隐私字段。

管理员：维护课程、教学班、受众、性质；可查询任意教学班名单。

## 6. 协议变化（供成员 A 参考）

建议新增或调整的操作（草案，最终以公共协议为准）：

- `COURSE_QUERY` 保持，学生视角返回当前可见课程（active 且满足受众）；
- `COURSE_SAVE` 调整为按课程、教学班分别维护；
- 新增受众与性质的维护操作；
- 新增 `COURSE_ROSTER`：教师或管理员查询教学班选课名单。
- `LoginRequest` / `LoginResponse` 无需改动：专业、工号等信息由服务端按 sessionToken
  反查，不随登录响应下发。

## 7. 前端展示调整

- 学生目录页：隐藏 active、学期两列；不可选的课程按钮置灰并显示原因；
- 新增“课程性质”作为查询维度；
- 教师端新增“选课名单”视图，名单不展示电话、邮箱等隐私字段；
- 管理员端新增课程、教学班、受众、性质的维护界面。

## 8. 已确认结论汇总

1. 受众范围保留“院系”层级，取值为 全校 / 院系 / 专业；
2. 课程性质按专业分表，取值为 必修 / 限选 / 任选 / 通选，且仅为展示与筛选信息；
3. 可见性 = active 且满足受众；学期仅作展示信息，不参与可见性筛选；
4. 选课窗口只影响可选性，窗口前后均可见但按钮置灰；
5. 不允许同一学生选同一课程的不同教学班；
6. 教师名单不展示电话、邮箱等隐私字段；
7. 学生专业字段直接存 `majorId`，转专业即改该字段，不新增转专业状态，不保留转专业历史；
8. 年级匹配用入学年份区间，不计算“当前年级”，不需要维护“当前学期/学年”。
