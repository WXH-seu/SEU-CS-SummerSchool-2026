# vCampus 校园商店模块说明

负责人：林道军（成员 E）。本模块同时承担商店业务与测试/部署职责。

## 1. 模块职责

校园商店实现「商品 → 购物车 → 订单」的完整购买链路，并支持管理员对商品与库存的维护。

### 1.1 角色与权限

| 角色 | 商品浏览 | 购物车 | 下单 | 订单查询 | 商品/库存维护 | 订单状态 |
| --- | --- | --- | --- | --- | --- | --- |
| STUDENT | 仅上架商品 | 可用 | 可用 | 仅本人 | 禁止 | 禁止 |
| TEACHER | 仅上架商品 | 可用 | 可用 | 仅本人 | 禁止 | 禁止 |
| ADMIN | 全部商品 | 禁止 | 禁止 | 全部订单 | 可维护 | 可更新 |

客户端只负责隐藏无权按钮，服务端 `StoreService` 必须再次校验会话与角色。

### 1.2 主要用例

- 商品浏览：关键字（编号/名称模糊）与分类筛选；学生/教师只能看到上架商品。
- 购物车：加入商品（校验库存与上架状态）、修改数量、数量为 0 即移除、移除单行。
- 下单：将购物车整单结算，事务内校验库存并扣减、清空购物车、生成订单与订单明细。
- 订单查询：学生/教师仅本人订单（含明细），管理员可看全部订单。
- 订单状态管理：管理员在 待付款 / 已付款 / 已发货 / 已完成 / 已取消 之间更新。
- 商品维护：管理员新增、编辑、删除商品；被购物车或订单引用的商品不可删除（建议先下架）。

## 2. Package 划分与调用链

商店功能按「客户端 → 通信 → 服务端业务 → 数据访问」分层，与学籍模块保持一致：

```text
vcampus-common    edu.seu.vcampus.common.dto        商店共享 DTO（Product/CartItem/Order/OrderItem/请求）
vcampus-server    edu.seu.vcampus.server.dao         StoreRepository 接口 + AccessStoreRepository
vcampus-server    edu.seu.vcampus.server.service     StoreService（权限、校验、下单事务边界）
vcampus-server    edu.seu.vcampus.server.dispatcher  StoreRequestHandler（Operation 分发）
vcampus-client    edu.seu.vcampus.client.service     StoreClientService（页面 → 协议请求）
vcampus-client    edu.seu.vcampus.client.ui          StorePanel/StoreProductPanel/StoreCartPanel/StoreOrderPanel/StoreEditors
```

调用链与 README 中的整体调用链一致：

```text
StoreProductPanel -> StoreClientService -> ClientConnection
  -> RequestMessage -> ClientHandler -> RequestDispatcher -> StoreRequestHandler
  -> StoreService -> StoreRepository -> AccessStoreRepository -> Microsoft Access
```

## 3. 数据库设计

新增四张表（由 `AccessStoreRepository` 在服务器启动时自动创建并写入演示数据）。
金额统一使用 Access `CURRENCY` 类型（定点小数），读取为 `BigDecimal`，禁止使用 `double`。

### 3.1 tblProduct 商品

| 字段 | Access 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| productId | TEXT(20) | 主键 | 商品编号 |
| productName | TEXT(64) | 非空、唯一 | 商品名称 |
| category | TEXT(32) | 可空 | 分类 |
| description | TEXT(255) | 可空 | 描述 |
| price | CURRENCY | 非空、>=0 | 单价 |
| stock | INTEGER | 非空、>=0 | 库存 |
| active | YESNO | 非空 | 是否上架 |

### 3.2 tblCartItem 购物车项

| 字段 | Access 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| cartItemId | TEXT(40) | 主键 | 购物车项编号 |
| userId | TEXT(32) | 非空 | 归属登录账号 |
| productId | TEXT(20) | 外键、非空 | 商品 |
| quantity | INTEGER | 非空 | 数量 |

约束：`UNIQUE(userId, productId)` 保证同一用户对同一商品只有一行，采用“更新或插入”。

### 3.3 tblOrder 订单

| 字段 | Access 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| orderId | TEXT(40) | 主键 | 订单号（ORD+UUID） |
| userId | TEXT(32) | 非空 | 下单人登录账号 |
| totalAmount | CURRENCY | 非空 | 订单总额 |
| statusName | TEXT(16) | 非空 | 状态 |
| orderTime | TEXT(19) | 非空 | 下单时间 `yyyy-MM-dd HH:mm:ss` |

### 3.4 tblOrderItem 订单明细

| 字段 | Access 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| orderItemId | TEXT(40) | 主键 | 明细编号 |
| orderId | TEXT(40) | 外键、非空 | 所属订单 |
| productId | TEXT(20) | 外键、非空 | 商品 |
| productName | TEXT(64) | 非空 | 下单时商品名快照 |
| unitPrice | CURRENCY | 非空 | 下单时单价快照 |
| quantity | INTEGER | 非空 | 数量 |
| subtotal | CURRENCY | 非空 | 小计 |

设计说明：订单与购物车均以登录账号 `userId` 为归属（学生与教师都可购物），因此不额外
引用 `studentId/teacherId`；订单明细保存商品名与单价的快照，避免商品改价/改名后订单失真。
删除商品前需检查 `tblCartItem` 与 `tblOrderItem` 引用，被引用时返回 CONFLICT。

### 3.5 演示数据

- P001 东南大学笔记本 12.50 / 100；P002 vCampus 纪念马克杯 25.00 / 50；
  P003 数据结构教材 45.80 / 30；P004 校园明信片套装 8.00 / 200；
  P005 运动水壶 30.00 / 0（演示缺货）；P006 旧版数据库教材 15.00 / 5（已下架，仅管理员可见）。

## 4. 通信协议

### 4.1 Operation（vcampus-common）

| Operation | 请求 body | 响应 body | 权限 |
| --- | --- | --- | --- |
| STORE_PRODUCT_QUERY | StoreQueryRequest（可空） | List<ProductDto> | 登录用户 |
| STORE_PRODUCT_SAVE | ProductDto | ProductDto | ADMIN |
| STORE_PRODUCT_DELETE | EntityIdRequest | String | ADMIN |
| STORE_CART_QUERY | 空 | List<CartItemDto> | 学生/教师 |
| STORE_CART_UPDATE | CartUpdateRequest | String | 学生/教师 |
| STORE_ORDER_CREATE | 空（整单结算） | OrderDto | 学生/教师 |
| STORE_ORDER_QUERY | 空 | List<OrderDto> | 登录用户 |
| STORE_ORDER_STATUS | OrderStatusRequest | String | ADMIN |

### 4.2 DTO

`ProductDto`、`CartItemDto`（含 getSubtotal）、`OrderDto`（含 List<OrderItemDto>）、
`OrderItemDto`、`StoreQueryRequest`、`CartUpdateRequest`、`OrderStatusRequest`。
所有 DTO 实现 `Serializable` 并声明 `serialVersionUID`，金额字段为 `BigDecimal`。

## 5. 关键业务规则

- 下单在 `AccessStoreRepository.createOrder` 中使用数据库短事务：读取购物车 → 校验上架与库存 →
  写订单/明细 → 扣库存 → 清空购物车 → 提交；任何一步失败即回滚，不产生脏数据。
- `StoreService.updateCart` 在下单前也做库存预校验（给用户即时反馈），下单事务内再次做权威校验。
- 响应码：参数错误 `INVALID_REQUEST`；库存不足/已下架/删除被引用 `CONFLICT`；
  记录不存在 `NOT_FOUND`；越权 `FORBIDDEN`；未登录 `UNAUTHORIZED`。

## 6. 客户端页面

- `StorePanel`：Tab 容器；管理员只有「商品 / 我的订单」，学生教师有「商品 / 购物车 / 我的订单」；
  切换页签自动刷新。
- `StoreProductPanel`：商品查询 + 加入购物车（学生/教师）+ 新增/编辑/删除（管理员）。
- `StoreCartPanel`：购物车列表、修改数量（0 即移除）、移除、结算下单；下单成功后自动跳转订单页。
- `StoreOrderPanel`：订单列表 + 选中订单的明细表；管理员可更新订单状态。
- 所有网络请求均在 `SwingWorker` 中执行，不阻塞事件分发线程。

## 7. 测试与验证

- `vcampus-common/.../StoreMessageSerializationTest`：商店 DTO 对象流序列化往返。
- `vcampus-server/.../StoreServiceIntegrationTest`：真实 Access 临时库上验证种子数据、
  购物车、下单扣库存、库存不足回滚、订单状态与权限、商品删除引用规则。

运行：仓库根目录 `mvn clean package` 后先启动
`java -jar vcampus-server/target/vCampusServer.jar`，再启动
`java -jar vcampus-client/target/vCampusClient.jar`。
服务器首次启动会自动创建 `tblProduct` 等商店表并写入演示商品。
