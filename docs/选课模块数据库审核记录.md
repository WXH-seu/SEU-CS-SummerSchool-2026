# 选课模块数据库审核记录

审核日期：2026-09-06  
审核人：成员 B（数据库总体设计）

## 1. 审核结论

当前 v1 选课模块具备完整的查询、选课、退课、课表与管理员维护链路，表间外键、
重复选课唯一约束和删除保护有效，可以用于当前阶段联调与演示。培养方案公开目录已经
独立保存于 `tblCatalogCourse`，不会污染实际开课表 `tblCourse`。

审核结果为“通过，保留 v2 改造项”。不建议在临近集成时直接破坏性重建现有表。

## 2. 已确认项

- `tblCourse.teacherId` 引用 `tblTeacher.teacherId`。
- `tblCourse.departmentId` 引用 `tblDepartment.departmentId`。
- `tblCourseEnrollment.studentId` 引用 `tblStudent.studentId`。
- `tblCourseEnrollment.courseId` 引用 `tblCourse.courseId`。
- `(courseId, studentId)` 唯一约束可防止同一学生重复选课。
- 课程已有选课记录时不能删除；学生有选课记录、教师有授课课程时不能从学籍模块删除。
- 选课时间采用 `TEXT(19)` 的 `yyyy-MM-dd HH:mm:ss` 格式，兼容 Java 8 与机房 Access。
- 学生端只查询开放课程，教师只查询本人课程，管理员才可维护课程。

## 3. 当前边界与风险

| 优先级 | 项目 | 影响 | 建议 |
| --- | --- | --- | --- |
| 高 | `tblCourse` 同时表达课程目录与教学班 | 同一课程不同教师、时间或学期难以表达 | v2 拆为课程目录与 `tblCourseSection` |
| 高 | 容量检查与写入尚未放在同一事务 | 多客户端同时抢最后名额时可能超额 | 成员 C 在 v2 中使用单事务或条件更新 |
| 中 | 上课时间冲突使用完整字符串相等 | 不能识别部分时间段重叠 | 后续结构化保存星期、起止节次 |
| 中 | 没有选课开始/结束窗口 | 只能用 `active` 近似表达开放状态 | 按 v2 草案增加时间窗口 |
| 中 | 学生尚未关联当前专业 | 无法按专业、年级限制可选范围 | 待组内确认后增加 `majorId` 与受众规则 |

## 4. v2 数据迁移建议

1. 保留 `tblCatalogCourse` 作为经审核的公开课程目录来源。
2. 新建 `tblCourseSection` 保存教师、学期、时间、地点、容量和选课窗口。
3. 将选课记录从 `courseId` 调整为引用 `sectionId`，迁移前生成旧编号映射。
4. 增加教学班受众与课程性质表，不在 `tblStudent`、订单或借阅表重复保存课程信息。
5. 在临时数据库完成结构迁移和回归测试后，再升级团队演示数据库。
